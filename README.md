# HeroCraft

Un RPG Voxel multijoueur sur une planète entière générée procéduralement, écrit en Rust avec WGPU.

## Architecture

Le projet est structuré sous forme de **Cargo Workspace** modulaire :

- `crates/common` : Types partagés (blocs, RPG, protocoles réseau, maths planétaires).
- `crates/voxel_engine` : Structures de données des chunks (32x32x32), palette compression, maillage glouton (Greedy Meshing).
- `crates/world` : Génération procédurale de planète (Cubed-Sphere, climats, biomes, grottes, villes, villages et ruines).
- `crates/server` : Serveur de jeu dédié autonome (60 Hz tickrate, autorité serveur).
- `crates/client` : Client graphique (moteur de rendu WGPU / Bevy, caméra, interface).

## Compilation et Lancement

### Jouer à plusieurs :
Tout passe par **`Échap > Multijoueur`** :
- **Ouvrir au réseau local** : un serveur démarre dans le jeu sur le monde en cours (il reprend et enregistre sa sauvegarde `saves/monde_<graine>/`), et vous y restez connecté. Les autres joueurs du réseau local voient la partie dans leur liste.
- **Parties sur le réseau local** : les parties ouvertes (ou les serveurs dédiés) du réseau local s'affichent d'elles-mêmes (annonces UDP sur le port 7778). Un clic sur `Rejoindre` suffit.
- **Rejoindre par adresse** : `ip` ou `ip:port` (port 7777 par défaut).
- **Se déconnecter** / **Fermer la partie** : retour au monde solo.

À la connexion, le serveur envoie la graine de sa planète et les chunks déjà modifiés : chaque client génère le reste lui-même. Les autres joueurs apparaissent comme des silhouettes dorées surmontées de leur nom. Le serveur fait vivre les créatures et montre à chacun celles de son voisinage. En ligne, `G` (nouvelle planète) est désactivé.

### Lancer le serveur dédié :
```bash
cargo run --release --bin herocraft_server -- [--port 7777] [--seed 2026] [--name "Mon serveur"] [--no-lan]
```
Le serveur écoute en TCP (port 7777 par défaut) à 60 TPS et s'annonce sur le réseau local (sauf `--no-lan`). Il fait autorité sur les blocs : il valide chaque bloc cassé ou posé (portée, contenu), l'enregistre dans `saves/serveur_monde_<graine>/` et le diffuse à tous les joueurs. Il relaie aussi leurs positions et le chat. Dans sa console : `stop` l'arrête en enregistrant le monde, `list` donne les joueurs en ligne, `seed` la graine, `say <message>` écrit à tous les joueurs, `help` rappelle ces commandes.

### Lancer le prototype client interactif :
```bash
cargo run --release --bin herocraft_client
```
Sans `--release`, le code du jeu est compilé sans optimisation : plus rapide à compiler, mais il tourne 5 à 10 fois plus lentement (les créatures à elles seules y prennent ~5 ms par image au lieu de ~0,6 ms). Le jeu le rappelle dans la console au lancement.
Pour rejoindre directement un serveur au lancement : `-- --connect 127.0.0.1:7777 --name Mat` (ou `HEROCRAFT_SERVER` et `HEROCRAFT_PSEUDO` dans `.env`).
Chaque partie solo, comme chaque appui sur « Nouvelle planète » (`G`), tire une graine au hasard, affichée dans la console. Pour retrouver une planète précise : `-- --seed 1234567890` (ou `HEROCRAFT_SEED` dans `.env`).

#### Configuration locale (`.env`) :
Copier `.env.example` en `.env` (non versionné). Les variables déjà définies dans l'environnement restent prioritaires.
- **`HEROCRAFT_MONITOR`** : écran où s'ouvre la fenêtre, par son nom Windows (`DISPLAY1`, `DISPLAY2`, `DISPLAY3`…). Sous WSLg, la correspondance avec l'écran Windows est retrouvée via `powershell.exe`, et la fenêtre passe par X11, car Wayland ne permet pas de la placer.

#### Taille de la planète :
Chaque face du cube fait 8 192 × 8 192 blocs (256 chunks de côté) : le tour de la planète fait 32 768 blocs, plus d'une heure et demie de marche, et une face se traverse en 26 minutes. La taille se règle en un seul point, `FACE_CHUNKS` dans `crates/world/src/edits.rs` (une puissance de deux : 32 redonne l'ancienne planète de 1 024 blocs par face) ; le rayon, les niveaux du relief lointain, les régions de villages, les nuages et les zones de créatures en découlent. Le bloc garde sa taille : seul le rayon grandit. Les continents, les plaques, les massifs et les climats grandissent avec la planète, tandis que les collines, les crêtes et les grottes gardent leur taille en blocs. Une sauvegarde est propre à une taille de planète (`saves/monde_<graine>_f8192/`), et un client ne rejoint qu'un serveur de même taille.

#### Récolte des matières premières :
Casser un bloc ou dépecer une bête fait tomber son butin au sol, que l'on ramasse en passant (champ `loot` des fiches de blocs et de créatures) :
- **Fibre** : herbes hautes (une fois sur trois à deux fois sur trois), buissons morts (avec parfois des bâtons), coton mûr. Trois fibres font une corde, et deux cordes avec quatre planches un établi.
- **Silex** : gravier (30 %), pierre (8 %) et pavés (5 %).
- **Récoltes** : les plantes sauvages mûres donnent leur récolte et leurs graines ; une jeune pousse donne sa graine. Les herbes hautes donnent parfois des graines de blé.
- **Bêtes** : une bête tuée reste couchée à terre 10 minutes. Un clic droit sur elle, couteau ou dague en main, la dépèce : viande, peaux, os, et ce qui leur est propre (laine du mouflon, plumes du faisan, fourrure et crocs du loup, griffes de l'ours, bois du cerf, défenses du sanglier…).

Un objet tombé au sol est dessiné en petite plaque tournante à son icône. En ligne, le serveur tire le butin des bêtes et l'envoie à celui qui les dépèce.

#### Agriculture :
- **Labourer** : clic droit avec une houe (`flintHoe`, `ironHoe`…) sur de l'herbe ou de la terre dégagée (une herbe haute visée disparaît) : elle devient de la terre labourée, **humide** s'il y a de l'eau à moins de 4 blocs (à sa hauteur ou juste en dessous), sèche sinon. Une terre labourée cassée rend de la terre.
- **Semer** : clic droit avec des graines (blé, carotte, pomme de terre, oignon, courge, soja, riz) sur une terre labourée : le semis se pose dessus et la graine est dépensée. Le riz ne pousse que sur une terre humide.
- **Pousser** : chaque plante passe ses quatre stades (semis, jeune pousse, plant, mûr), de 2 à 4 minutes par stade sur une terre humide, deux fois plus sur une terre sèche, et plus du tout si on lui retire sa terre labourée. Les saisons et la météo s'en mêlent : la pousse est entière au printemps et en été, ralentie en automne et plus encore en hiver (peu sous les tropiques), un peu plus vive sous la pluie, et arrêtée sous la neige et dans le gel. Une plante mûre se casse pour sa récolte (voir plus haut) ; cassée avant, elle rend sa graine. Casser la terre labourée fait tomber la plante qu'elle porte.
- Les cultures sont décrites par `assets/cultures/` (graine, stades, durée d'un stade) : voir [assets/cultures/README.md](assets/cultures/README.md). Les plantes semées sont enregistrées avec le monde (`cultures.json`) ; en ligne, c'est le serveur qui les fait pousser. Les champs des villages restent tels que le générateur les a posés, jusqu'à ce qu'on les récolte et ressème.

#### Élevage :
- **Attirer** : vaches et mouflons suivent le joueur qui tient du blé, lapins et cerfs des carottes (le lapin aime aussi le trèfle, le cerf les pommes de terre), faisans des graines. Ils approchent jusqu'à 2 blocs et ne fuient plus tant qu'on la tient, à moins de 10 blocs.
- **Apprivoiser** : clic droit sur la bête avec sa nourriture en main. Chaque repas a une chance sur trois de l'apprivoiser : des cœurs s'élèvent au-dessus d'elle et le chat l'annonce. Une bête craintive apprivoisée ne fuit plus, elle regarde.
- **Reproduire** : une bête apprivoisée et adulte nourrie devient amoureuse pendant 30 secondes (cœurs) et va vers la bête amoureuse de son espèce la plus proche, à moins de 8 blocs. Réunies, elles donnent un petit, apprivoisé d'office et de leur troupeau, puis ne peuvent plus aimer pendant 5 minutes.
- **Pondre** : un faisan apprivoisé et adulte pond un œuf de faisan toutes les 5 à 10 minutes, laissé à ses pieds (il se mange et rassasie de 2).
- **Grandir** : le petit naît à la moitié de la taille d'un adulte et grandit en 6 à 12 minutes selon l'espèce ; chaque repas lui fait gagner un dixième de sa croissance.
- Apprivoisement et âge sont enregistrés avec la population (`creatures.json`) ; en ligne, le serveur tient l'élevage et voit ce que chaque joueur tient en main. Chaque espèce qui s'élève le décrit dans le champ `breeding` de sa fiche (voir [assets/creatures/README.md](assets/creatures/README.md)).

#### Végétation :
Le générateur pose la végétation selon le biome : chênes, bouleaux et bosquets roux en forêt, sapins en taïga et sur les alpages, grands arbres et sous-bois touffus dans la jungle, acacias en savane, cactus au désert, palmiers sur les plages chaudes, buissons un peu partout, et quelques bosquets dans les plaines. Au sol poussent des herbes hautes, des massifs de fleurs d'une même espèce dans les prairies, des iris et de la lavande en altitude et dans la toundra, des champignons sous les arbres et des buissons morts dans les régions sèches. Par taches rares poussent aussi des plantes sauvages mûres : blé, carottes, pommes de terre et oignons dans les prairies, courges et soja en forêt, riz dans la jungle, coton en savane. Tout se déduit de la graine, sans rien enregistrer : un arbre ne déborde que de 3 blocs de son tronc, au plus un par case de 6 × 6 blocs. On traverse les herbes et les fleurs (un bloc posé en visant une herbe haute prend sa place) ; on bute contre les troncs et les feuillages, et on peut marcher dessus. Le relief lointain ne montre pas encore les arbres : ils apparaissent avec les chunks voxel.

#### Créatures :
Les 19 créatures du bestiaire (reprises du module `HeroBestiary` de la branche `develop`) sont dessinées avec leurs modèles glTF animés et leurs textures. Lapins, faisans, cerfs, loups, ours, sangliers, vaches et mouflons peuplent la planète selon le biome, sur l'herbe, la terre, le sable ou la neige : chaque zone de 32 × 32 blocs reçoit une fois pour toutes la population que lui destine la graine du monde, et plus rien n'apparaît ensuite. Une bête tuée ne revient pas. Les créatures des profondeurs et des mondes démoniaques n'apparaissent pas encore d'elles-mêmes. Toutes se promènent au hasard : elles franchissent les marches d'un bloc, évitent l'eau, les murs et les à-pics, et tombent dans les trous creusés sous elles. Leurs pattes bougent à la vitesse où elles avancent. Loin de tout joueur, une zone s'endort : ses bêtes ne bougent plus et reprennent là où elles étaient quand un joueur revient. La population (zones déjà peuplées, bêtes, positions, vie) est enregistrée dans `creatures.json`, dans la sauvegarde du monde. En solo, elles vivent dans le jeu et s'arrêtent avec le menu ; en ligne, c'est le serveur qui les fait vivre. Chaque espèce est décrite par un fichier de `assets/creatures/` : ajouter une bête, c'est ajouter un fichier et son modèle. Voir [assets/creatures/README.md](assets/creatures/README.md).

Les menus et le HUD reprennent l'habillage de l'ancien Terasology (branche `develop`) : panneaux de planches cerclés de fer, boutons de bois, plaque de titre en métal, cases d'inventaire et cases à cocher en pixel art, polices Grenze et Uncial Antiqua. Les textures et les polices sont dans `crates/client/assets/ui/` (licences dans [LICENCE.md](crates/client/assets/ui/LICENCE.md)). Pour voir les menus sans lancer le jeu : `HEROCRAFT_CAPTURES=captures cargo test -p herocraft_client snapshot_menus -- --ignored` enregistre une capture PNG de chaque page (fond au choix avec `HEROCRAFT_CAPTURES_FOND=image.png`, taille avec `HEROCRAFT_CAPTURES_TAILLE=1280x720`).

#### Créateur de héros :
À la première arrivée au sol dans un monde, le créateur de légende (repris du module `HeroClasses` de la branche `develop`) s'ouvre en plein écran. Trois étapes : **le corps** à la forge (10 espèces et leurs sous-races, taille, corpulence, peau, visage, pilosité, tenue, ou « Tirer au sort »), **la voie** au râtelier (15 voies en trois familles), puis **le nom**. Le héros tourne à gauche dans son aperçu (glisser pour le tourner à la main), peint texel par texel comme la maquette de référence. Le baptême vérifie chaque choix, scelle la légende dans `saves/<monde>/heros.json` et règle la hauteur des yeux sur la taille du héros ; il part les mains vides. En vue à la troisième personne (premier cran de molette depuis la vue subjective, la caméra se tient à quelques blocs derrière lui), le héros est dessiné avec sa planche, sa taille et sa carrure, bras et jambes balancés par la marche. En ligne, le serveur vérifie la légende à son tour et en prend la voie. Les données viennent de `assets/heros/atlas.json`.

#### Villes, villages et ruines :
La planète porte des villes fortifiées, des villages et des ruines, posés par le générateur selon la graine : chaque face est découpée en régions de 2 048 × 2 048 blocs, et chaque région accueille au plus une ville ou un village, près de son centre, sur un site qui s'y prête (terre ferme, relief assez plat, biome). Deux établissements voisins sont ainsi à 1 300 à 2 800 blocs l'un de l'autre (1 800 en moyenne), soit 4 à 9 minutes de marche. Entre eux, des ruines isolées, environ trois par région. Une graine donne une cinquantaine de villes et villages et plus d'une centaine de ruines, toujours les mêmes, pour le client, le serveur et tous les joueurs en ligne.
- **Villes** : un damier de rues pavées entre des remparts crénelés, une tour à chaque angle, une porte au milieu de chaque côté, une grand-place avec sa fontaine et ses étals de marché, des lampadaires aux carrefours, une église à clocher donnant sur la place, une ou deux tavernes, une forge et une vingtaine de maisons de briques ou de planches, souvent à étage (une échelle y monte).
- **Villages** : un puits couvert sur une petite place, deux à quatre chemins de gravier bordés de maisons, souvent une chapelle, une taverne ou une forge, des lampadaires, des champs irrigués (blé, carottes, pommes de terre, courges) et parfois une grange à grande porte.
- **Bâtiments** : maisons de 5 à 9 blocs de côté, à toit à deux ou quatre pans, avec ou sans cheminée ni porche, une torche posée dans un coin à chaque étage ; l'église a des bancs, un autel et un clocher à abat-sons ; la taverne, des tables et une cheminée ; la forge est un appentis ouvert avec âtre, fourneau et enclume ; la grange abrite des bottes de blé.
- **Ruines** : temple sur podium aux colonnes brisées et à l'autel orné d'un cristal, vieille tour ronde éventrée, ou hameau de maisons effondrées.

- **Éclairage** : les torches des maisons, des fontaines et des lampadaires (un socle de pierre, un fût de barrière de la matière des remparts et une lanterne au sommet) éclairent la nuit les rues et les intérieurs d'une lumière chaude ; elle passe par les portes et les fenêtres, pas à travers les murs.

Les matériaux suivent le climat : maisons à toits plats blanchis à la chaux dans les déserts et les savanes, rondins de pin et toits de pavés dans la taïga et la toundra, planches et toits d'escaliers ailleurs. Chaque bâtiment a un plancher plat : des fondations comblent la pente, et le relief est dégagé au-dessus. Rues, champs et remparts suivent le terrain. Tout se casse et se construit comme le reste du terrain. Les structures ne se voient que dans la zone de blocs autour du joueur, pas encore sur le relief lointain.
Pour aller voir : `-- --visiter ville` (ou `village`, `ruines`, suivi au besoin d'un numéro : `--visiter village 3`) fait apparaître au bord de l'établissement de ce genre. `cargo run -p herocraft_world --release --example settlements -- <graine>` les liste tous, et `-- <graine> <n°>` dessine le plan de l'un d'eux vu de dessus.

#### Blocs et objets :
Les 135 blocs et 523 objets des modules de la branche `develop` (`CoreAssets`, `HeroSurvival`, `HeroCrafting`, `HeroEquipment`, `HeroBestiary`…) sont décrits chacun par une fiche JSON, lue au lancement : `assets/blocks/` pour les blocs (nom, couleurs, textures, forme, passage, son, ce qu'il donne une fois cassé), `assets/items/` pour les objets (nom, description, taille de pile, icône, caractéristiques). Ajouter un bloc ou un objet, c'est ajouter une fiche. Fleurs, herbes et pousses sont dessinées en deux panneaux croisés qu'on traverse ; un bloc qui éclaire (torche, lave, clochelueur) répand sa lumière jusqu'à 14 blocs, arrêtée par les murs ; les barrières se relient d'elles-mêmes à leurs voisines et aux murs ; le verre et la glace laissent voir les faces derrière eux. Chaque fiche porte aussi les recettes qui fabriquent son bloc ou son objet (455, reprises de `HeroCrafting`), et les établis sont décrits dans `assets/stations/` : établi, fourneau, tour de lapidaire, et forge astrale à deux niveaux (la forge ultime en est le niveau 2). Les objets ne servent à rien pour l'instant (pas encore de combat ni de nourriture). Voir [assets/blocks/README.md](assets/blocks/README.md), [assets/items/README.md](assets/items/README.md) et [assets/stations/README.md](assets/stations/README.md).

#### Blessures et mort :
Une chute de plus de 5 blocs blesse : l'écran rougit, ses bords s'assombrissent de rouge et la vue penche un instant, avec un souffle coupé. Sous 30 % de vie, les bords de l'écran battent en rouge. À la mort, la vue s'effondre au sol et un écran « Vous êtes mort » donne la cause ; le bouton `Réapparaître` (ou `Espace`) ramène au point d'apparition, jauges pleines, après 2 secondes.

La **faim** se lit sur la jauge de satiété, sous l'endurance. Elle baisse doucement avec le temps (un ventre plein tient 25 minutes) et plus vite au sprint (6 minutes de course). Sous 25 %, « Vous avez faim » : la jauge clignote, la vie ne remonte plus et l'endurance revient deux fois moins vite. À zéro, « Vous mourez de faim » : la vie baisse d'un demi-point par seconde, jusqu'à 10 % de son maximum (la faim affaiblit mais ne tue pas). Pour manger, prendre un aliment en main dans la barre d'objets et faire un clic droit : il rend la satiété indiquée dans sa bulle (`Satiété`, de 2 pour un oignon cru à 72 pour un ragoût). On ne mange pas le ventre plein. La satiété est enregistrée avec la progression du monde solo ; en ligne, c'est le serveur qui la tient. La mort et `/heal` la remplissent.

#### Contrôles du prototype :
Toutes les touches se changent dans `Échap > Commandes` (clic sur une touche, puis appui sur la nouvelle). Elles sont enregistrées dans `config/controles.json`.
- **Souris** : en jeu au sol, le curseur est capturé et la souris oriente le regard. Le menu Échap et la vue satellite le font réapparaître.
- **`Z Q S D`** (AZERTY, `W A S D` en QWERTY) : se déplacer. **`Ctrl`** : sprinter.
- **`Espace`** : sauter (1,3 bloc de haut, un peu plus d'une demi-seconde en l'air : de quoi franchir une marche d'un bloc). **Double `Espace`** : s'envoler ou se poser ; en vol, `Espace` monte et **`Maj`** descend (se poser au sol termine le vol).
- **Clic gauche** (maintenu) : casser le bloc visé par le réticule (son contour est surligné). Il se fissure peu à peu, plus ou moins vite selon sa matière (0,3 s pour les feuilles ou la neige, 0,5 s pour la terre, 1,5 s pour la pierre, 5 s pour l'obsidienne ; les autres blocs selon la dureté de leur fiche), puis tombe au sol en petit cube, attiré puis ramassé dans l'inventaire quand on passe à moins de 2,5 blocs (l'herbe donne de la terre, l'eau et la lave ne se ramassent pas ; un objet oublié disparaît au bout de 5 minutes, et un inventaire plein le laisse au sol). **Clic droit** : poser contre la face visée le bloc de la case choisie de la barre d'objets. Garder le clic droit enfoncé répète la pose ; garder le clic gauche enfoncé enchaîne les blocs. Les blocs modifiés sont enregistrés dans `saves/monde_<graine>/chunks/`.
- **Habitants** : clic droit sur un habitant qui a des échanges (forgeron, marchand…) ouvre l'écran des échanges ; un habitant sans rien à échanger (sans métier, garde…) répond dans le chat, en vert, et enchaîne ses répliques à chaque clic : seuls les joueurs à moins de 16 blocs de lui l'entendent. Un habitant ne se frappe que si le clic gauche a commencé sur lui (celui qui passe devant un bloc en train de casser n'est pas touché). Frapper un habitant prévient son auteur dans le chat : les gardes de la ville s'en prennent à lui, et à lui seul, pendant 20 secondes ; le tuer est annoncé à tous et les gardes le recherchent 3 minutes. Les gardes se tiennent de part et d'autre des portes de la ville (ou du puits du village) sans les quitter, et chaque badaud du rassemblement autour de la fontaine prend son propre bloc.
- **Barre d'objets** (en bas de l'écran) : **`1`** à **`9`** ou la **molette** choisissent la case. **`F`** ouvre l'inventaire (27 cases de sac + la barre, piles de 64) : clic gauche pour prendre, poser, fusionner ou échanger une pile, clic droit pour en prendre la moitié ou poser un seul bloc. À gauche, le héros tourne entre ses **8 cases d'équipement** (tête, torse, jambes et pieds d'un côté ; cape, amulette et deux anneaux de l'autre), avec la protection totale de ce qu'il porte : chaque case ne prend que ce qui s'y porte (champ `slot` des fiches d'objets), s'éclaire d'or quand la pièce tenue à la souris peut s'y poser, et **Maj + clic** enfile une pièce (ou l'échange avec celle portée) ou l'ôte. Ni le ramassage ni la fabrication ne touchent à ce qui est porté. Les armes restent dans la barre d'objets, et la protection n'amortit pas encore les coups. À droite, le panneau **Fabrication** liste les recettes faites à la main (planches, bâtons, corde, établi…), en onglets par rubrique (Armes, Armures, Outils, Cuisine, Matériaux, Construction, avec le nombre de recettes faisables) et, pour l'équipement, en sections par palier (bois, os et peau, silex, cuivre… étherium) qui ne s'ouvrent seules que s'il y a de quoi faire ; l'onglet choisi est retenu pour chaque établi, et la recherche ignore les accents. Celles qu'on peut faire viennent en tête : clic gauche pour la faire une fois, clic droit pour en faire autant que possible. **Clic droit sur un établi** (établi, fourneau, tour de lapidaire, forge astrale) ouvre le même écran avec ses recettes en plus ; accroupi, le clic droit pose un bloc contre lui. L'inventaire est enregistré avec le monde (`saves/monde_<graine>/inventaire.json`) ; en ligne, un inventaire à part est gardé pour la planète du serveur (`saves/en_ligne_<graine>/`).
- **`Alt` + molette** : zoom continu de la vue, du sol à l'orbite. En vue satellite, la molette seule suffit et clic + glisser tourne la planète.
- **`V`** : vue au sol / satellite. **`B`** : réinitialiser la vue. **`G`** : nouvelle planète. **`U` / `Y`** : filtres plaques tectoniques / courants marins. Un ancien fichier de contrôles qui avait encore E, F, R ou T sur ces actions les rend aux compétences.
- **`C`** : roue des compétences. Chaque niveau donne un point de compétence (100 xp pour le niveau 2, puis 100 de plus à chaque palier) ; un clic sur une compétence ouvre sa fiche, d'où l'on y investit un point (jusqu'au rang 3), pourvu que celles qu'elle demande soient apprises. La roue reprend celle du carnet Planner (fiche #138) : les 180 compétences des 15 classes, chaque classe de sa couleur, du niveau 1 au centre jusqu'à l'ultime au bord ; on peut apprendre dans toutes les classes. La roue fait loupe sur une classe : tournée en haut, elle prend près de la moitié du cercle avec ses compétences nommées, les autres se resserrent ; molette, flèches ou clic sur une part pour tourner. Chaque compétence a son fichier, `assets/skills/<classe>/<id>.json` (identifiants anglais ; les classes et leurs couleurs dans `assets/skills/classes.json`, l'icône 48 × 48 à côté, `<id>.png`) : sa place sur la roue (`wheel`), ses règles (`cast` : coût, recharge, geste, zone, cibles, effets), ses visuels et ses sons. `PLANNER_TOKEN=… python3 tools/importer_roue_competences.py` reprend du carnet les noms, descriptions et places sur la roue sans toucher au reste. Une compétence sans `cast` s'apprend mais est marquée « pas encore jouable » sur sa fiche ; toutes se jouent, sauf les nœuds qui donnent d'autres sorts (éléments, Fusion). Les ruées et bonds (`movement` : `dash`, `leap`) emportent le héros ; il peut aussi léviter (`hover`), être tiré par un grappin vers le bloc visé, où il se hisse sur le rebord, ou vers l'ennemi touché (`grapple`), ou se téléporter près de l'ennemi touché, à une place et avec un regard donnés par rapport à lui (`teleport` : `behind`, `above`, `side`, `face`, `delay`) ; une bête peut être projetée en l'air (`launch`), étourdie tant qu'elle vole, puis rabattue au sol (`slam`), et une seconde frappe peut suivre la première sur les mêmes ennemis (`follow_up`). les renforcements de vitesse et de régénération agissent. L'invisibilité (`invisible`) cache le joueur aux bêtes, et sa première attaque le dévoile en coup critique (dégâts doublés) ; les renforcements `critical` et les marques (`mark`) ajoutent des chances de critique ; une bête aveuglée (`blind`) ne voit plus qu'à un bloc et demi ; une bête provoquée (`taunt`) poursuit le lanceur. L'Intervention Suprême (`revive`) relève sur place les alliés tombés, avec la moitié de leur vie, tant qu'ils n'ont pas réapparu. Certaines bêtes ralentissent (`slow`) ou étourdissent (`stun`) le joueur qu'elles frappent : l'étourdi ne bouge, ne saute, ne frappe ni ne lance plus rien ; ces états s'affichent sous les jauges. Les formes complètes du Druide (`form`, une espèce de `assets/creatures/`) remplacent le héros par la bête : plus de barre d'objets, d'inventaire ni de barre de compétences, le clic gauche et le clic droit lancent ses deux attaques (`form_attacks`). Un nœud peut donner plusieurs compétences (`grants` : les quatre éléments du Sorcier élémentaire se séparent chacun en deux sorts). La Fusion (`fusion` dans `elementalist/fusion.json`) mêle les deux derniers sorts élémentaires lancés : deux éléments différents donnent leur mélange (`mixes`), s'il est appris (un mélange ne se lance que par elle), deux sorts du même élément relancent le dernier amplifié (`amplify` : dégâts, soins et boucliers ×1,75, zone ×1,3, coût ×1,5, visuels en plus) ; sa case montre l'icône de ce qu'elle lancerait. La Marque du Martyr (`link`) fait encaisser au chapelain une part des dégâts de l'allié, la Marque Détonante (`homing`) se pose sur la bête marquée, le saignement de la Chasse Mortelle s'aggrave quand la bête bouge (`moving`) et l'Œil de Faucon allonge la portée (renforcement `range`). Une zone peut rester posée (`zone` : sa durée, `follow` pour une aura qui suit le lanceur) : ses dégâts et soins par seconde, ralentis, aveuglements, invisibilités et renforcements valent pour qui s'y trouve, entrants compris, et cessent dès qu'on en sort (Nuage Miasmatique, Sanctuaire, Brume Apaisante, Aura de Vigueur…). Une frappe peut déclencher des effets : par ennemi touché (`on_hit`), si elle manque (`on_miss`, avec `sacrifice` qui blesse le lanceur sans le tuer), autour de ceux qu'elle tue (`on_kill`). Un renforcement peut suivre la vie manquante (`per_missing_health`), porter des effets autour des cibles de chaque attaque, coups d'arme compris (`rider`), partir en nova quand le joueur tombe, qui survit alors (`on_death`), ou viser une famille de créatures (`against`, les `tags` des espèces : `shadow` pour les créatures de l'ombre). `cleanse` retire ralenti, étourdissement et dégâts sur la durée ; `restore` rend mana et endurance, `mana_regen` et `stamina_regen` les font remonter plus vite ; un bouclier peut rendre en mana une part de ce qu'il absorbe (`absorb_to`) ; un lien peut ne servir qu'un coup (`hits`). La cible `summons` vise les invocations du lanceur, qu'on peut soigner, protéger d'un bouclier ou presser (renforcement `haste` : cadence de tir) ; une invocation peut avancer droit devant en repoussant les ennemis (`advance`, le Rempart Tellurique). Un joueur peut lever sa garde (`guard`) : pendant sa fenêtre, les coups des bêtes qui arrivent de face (`arc`, en degrés) perdent leur part bloquée (`block`), jusqu'à un nombre de coups (`hits`) ou pour certains types de dégâts seulement (`kinds`) ; un coup paré ne ralentit, n'étourdit ni ne repousse, et peut déclencher une riposte autour de l'attaquant ou du joueur (`counter`) ou renvoyer les dégâts bloqués (`reflect`). Une garde qui riposte et ne pare rien voit sa recharge doublée (`miss_cooldown`). Une immunité (`immune`) fait ignorer l'étourdissement, le ralenti, le recul, l'attraction ou les dégâts (Phalange, Égide Divine, Maître de guerre du Néant). Certaines bêtes repoussent le joueur qu'elles frappent (`knockback` dans leur attaque : brute, sanglier, ours) et d'autres se gardent de face (`guard` : garde, voyageur armé, chevalier de la mort), une garde que Brise-Garde fait tomber (`break_guard`). Un saignement qui vide un joueur le tue. En solo, la progression est enregistrée avec le monde (`saves/monde_<graine>/progression.json`) et un bouton d'essai donne 100 xp ; en ligne, c'est le serveur qui la tient.
- **Barre de compétences** (à droite de la barre d'objets) : **`A`**, **`E`**, **`R`**, **`T`** (AZERTY ; Q, E, R, T en QWERTY) lancent la compétence de leur case, dans la direction du regard (sur le bloc visé pour les zones à distance). Une compétence apprise se pose seule dans la première case libre ; sa fiche, sur la roue, a les boutons qui la placent dans une case. La case montre l'icône (une pastille à la couleur de la classe si elle manque), la recharge qui se vide et se grise quand la mana ou l'endurance manquent ; un refus s'affiche au-dessus. Le héros fait le geste de la compétence (`assets/hero/animations/`) ; à la première personne, ses bras et l'objet qu'il tient entrent dans le champ le temps du geste. Les effets (`assets/effects/`) sont des lueurs ajoutées avant le bloom. En ligne, le serveur juge le lancement et la frappe ; en solo, le jeu applique les mêmes règles (`herocraft_world::SkillRunner`). La barre est gardée dans `config/barre_competences.json`. `/cast <id>` lance une compétence depuis le chat.
- **`M`** : carte. Vue de dessus, nord en haut, centrée sur le joueur à l'ouverture : relief ombré, mers, villes, villages et ruines avec leur nom, chemins. Elle suit la courbure de la planète et passe d'une face à l'autre sans couture. Molette ou `+`/`-` : zoom de 1 à 64 blocs par pixel (de 320 m à 20 km de côté) ; glisser : déplacer ; clic droit : poser ou retirer un repère ; survol : distance et direction depuis le joueur. Le terrain est relevé dans un fil à part : la carte s'affiche en une fraction de seconde, les chemins arrivent ensuite. Les noms des lieux se déduisent de la graine, les mêmes pour tous les joueurs. En haut de l'écran, au sol, la **boussole** donne le cap du regard, les établissements à moins de 1,6 km et le repère, avec le nom et la distance de celui que l'on vise.
- **`Entrée`** : chat (voir plus bas). **`Échap`** : menu de pause. **`F9`** : rapport de profilage.

#### Chat et commandes :
**`Entrée`** ouvre le chat en bas à gauche (la souris est libérée, les touches ne pilotent plus le joueur). `Entrée` envoie, `Échap` referme. En ligne, le message part à tous les joueurs du serveur ; en solo, il reste à l'écran. Les dernières lignes restent affichées 10 secondes une fois le chat fermé. **`↑` / `↓`** rappellent les lignes déjà envoyées, **`Tab`** complète le nom d'une commande, d'un bloc ou objet (`/give`), d'une créature (`/summon`) ou d'un joueur (`/tp`), et passe d'une suite à l'autre.

Une ligne qui commence par `/` est une commande (en anglais) :
- `/help [command]` : liste des commandes, ou détail de l'une.
- `/tp <latitude> <longitude> [height]` : téléportation au sol (degrés), éventuellement quelques blocs au-dessus (en vol). `/tp <player>` : à côté d'un autre joueur. `/spawn` : retour au point d'apparition. `/pos` : latitude, longitude, altitude et bloc.
- `/time` : heure locale. `/time set <0-24|hh:mm|sunrise|day|noon|sunset|night|midnight>` : règle l'heure là où l'on est. `/time speed <factor>` : vitesse du ciel (1 : jour de 20 min, 0 : ciel figé, solo seulement). En ligne, l'heure est celle du serveur, la même pour tous : `/time set` la change pour tout le monde.
- `/weather` : temps qu'il fait, température et vent. `/weather <clear|cloudy|rain|storm|snow>` force un temps, `/weather auto` rend la main à la nature. `/season` : saison et jour de l'année là où l'on est ; `/season <spring|summer|autumn|winter>` avance l'horloge jusqu'au début de cette saison (dans l'hémisphère nord). En ligne, ces réglages valent pour tous les joueurs.
- `/seed` : graine de la planète. `/planet [seed]` : nouvelle planète, au hasard ou de cette graine (solo).
- `/give <item> [count]` : blocs ou objets dans l'inventaire (identifiant de la fiche, comme `cobbleStone`, ou nom affiché).
- `/fly` : voler ou se poser. `/speed <factor>` : vitesse de déplacement (0,1 à 20, 1 : normale).
- `/summon <creature> [count]` : créatures devant soi (`loup`, `vache`…). `/heal` : jauges pleines. `/xp <amount>` : expérience (chaque niveau gagné donne un point de compétence). En ligne, ces trois commandes passent par le serveur.
- `/list` : joueurs en ligne. `/clear` : vide le chat.

#### Météo et saisons :
L'année compte quatre saisons de 5 jours (une année dure 8 heures de jeu). L'hémisphère sud a les saisons inverses du nord, et sous les tropiques elles se sentent à peine. La température dépend de la latitude, de l'altitude et de la saison ; sous 0 °C, la pluie tombe en neige. Le temps naît d'un bruit qui dérive lentement, plus pluvieux là où le climat est humide (forêts, jungles) que dans les déserts : à peu près 17 % du temps sous la pluie, 2 % sous l'orage. Il se calcule à partir de la graine et de l'horloge du ciel, si bien que tous les joueurs voient le même ciel sans rien échanger d'autre que l'heure.
- **Rendu** : les nuages se font plus nombreux puis plus sombres quand le temps se gâte ; le ciel vire au gris, le soleil et les ombres s'effacent, les couleurs se ternissent. Pluie et neige tombent dans un carré de 41 × 41 blocs autour du joueur et s'arrêtent sur le premier bloc porteur : on est à l'abri sous un toit, un arbre ou dans une grotte. Le sol mouillé brille, la neige blanchit le dessus des blocs et y reste un moment après l'averse. Sous l'orage, des éclairs illuminent la scène, suivis du tonnerre avec le retard que donne la distance.
- **Saisons** : les feuillus verdissent au printemps, roussissent en automne (orange, rouge ou or selon les bosquets) et se dépouillent en brun gris l'hiver ; l'herbe jaunit à la fin de l'été. Les conifères restent verts.
- **Son** : pluie qui s'étouffe sous un abri, vent qui forcit avec la tempête, tonnerre ; pas d'oiseaux sous la pluie.
- **Créatures** : sous l'orage ou une forte pluie, les bêtes qui ne sortent pas en toute saison se mettent à l'abri et ne bougent plus. Les ours hibernent l'hiver (`"hibernation": true` dans la fiche de l'espèce).
- **Cultures** : `herocraft_world::crop_growth_factor(&sample)` donne le facteur de pousse d'un champ (entière au printemps et en été, un peu plus vive sous la pluie, ralentie en automne, nulle sous la neige et dans le gel d’hiver), pour les champs cultivés.
- **Horloge** : en solo, l'heure, la saison et le temps forcé sont enregistrés dans `saves/monde_<graine>/temps.json`. Le serveur garde la sienne dans sa sauvegarde, l'envoie à l'arrivée puis toutes les 5 secondes, et répond aux commandes de console `weather [clear|cloudy|rain|storm|snow|auto]` et `season <spring|summer|autumn|winter>`.
- **Performances** : les gouttes sont animées par le shader de sommets (au plus ~6 700 petits quadrilatères, 2 gouttes par colonne au lieu de 4 sur une puce intégrée) ; le processeur ne relit le dessus des colonnes que quand le joueur change de bloc. Sous un ciel très couvert, les passes d'ombre sont sautées, ce qui rend l'orage plutôt moins coûteux que le beau temps.

#### Son :
Pas (selon le bloc sous les pieds : herbe, terre, pierre, sable, neige, bois, eau), saut, réception, blessure, coups portés au bloc qu'on casse, blocs cassés et posés (aussi ceux des autres joueurs proches), et ambiance : vent qui forcit en altitude, oiseaux le jour, grillons la nuit, étouffés sous un plafond. Les sons sont synthétisés au lancement, sans fichier audio. Les volumes (général, bruitages, ambiance) se règlent dans `Échap > Options > Son` et sont enregistrés dans `config/audio.json`. Sans sortie audio, le jeu tourne en silence.

Sous Linux et WSL, la compilation demande les en-têtes ALSA, une fois pour toutes :
```bash
sudo apt install libasound2-dev pkg-config
```
Le son passe par PulseAudio (ou PipeWire), ce que WSLg fournit d'office. Pour écouter tous les sons hors du jeu : `cargo test -p herocraft_client ecouter_les_sons -- --ignored --nocapture` (ou `exporter_les_sons` pour les écrire en WAV dans `target/sons/`).

### Profiler les performances :
```bash
cargo run --release --features profiling --bin herocraft_client
```
Le rapport est écrit dans `./profiling/` à la fermeture (ou avec `[F9]`). Voir [docs/PROFILAGE.md](docs/PROFILAGE.md).

### Banc d'essai automatique (FPS par fonctionnalité) :
```bash
cargo run --release --bin herocraft_client -- --benchmark
```
Le jeu joue seul une suite de phases d'environ 11 s (ombres, nuages, rayons, bloom, créatures, distance LOD, vues, marche, vol), puis écrit un rapport dans `./benchmark/` et se ferme. Voir [docs/BANC_ESSAI.md](docs/BANC_ESSAI.md).

### Lancer les tests unitaires :
```bash
cargo test
```

### Compilation rapide :
La compilation incrémentale est active : après une modification, `cargo build` ne recompile que ce qui a changé (environ 1,5 s au lieu de 5 s). Garder Rust à jour (`rustup update`) : depuis Rust 1.90, l'éditeur de liens `rust-lld`, bien plus rapide, est utilisé par défaut sous Linux et WSL.

**Compilation depuis Windows sur un partage WSL** (`\\wsl.localhost\...`, par exemple depuis un IDE Windows) : ce système de fichiers ne supporte pas les verrous de la compilation incrémentale. La désactiver côté Windows seulement, une fois pour toutes, dans PowerShell :
```powershell
setx CARGO_INCREMENTAL 0
```
Cette variable n'est pas transmise à WSL, où la compilation incrémentale reste active. Compiler depuis un terminal WSL reste le plus rapide.
